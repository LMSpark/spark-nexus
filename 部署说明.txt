## 环境要求

- Docker Desktop 或 Docker Engine
- Java 17

- Node.js 18+ 和 npm
- 可用端口：`3806`、`6379`、`9000`、`9001`、`8580`、`5683`、`5684`

## 一键启动本地依赖

在项目根目录执行：

```powershell
cd D:\物业管理
docker compose -f deploy\docker-compose.yml up -d mysql redis minio
docker inspect -f "{{.State.Health.Status}}" spark-nexus-property-mysql
```

看到 `healthy` 后再恢复数据库或启动后端。

## 恢复数据库

如果是新环境，先启动 MySQL 容器，再把导出的 SQL 复制到容器中执行：

```powershell
cd D:\物业管理
docker cp deploy\property_revenue_full_20260604-194330.sql spark-nexus-property-mysql:/tmp/property_revenue_full.sql
docker exec spark-nexus-property-mysql sh -lc "mysql -uroot -proot123456 --default-character-set=utf8mb4 < /tmp/property_revenue_full.sql"
```

恢复后检查：

```powershell
docker exec spark-nexus-property-mysql mysql -uroot -proot123456 -N -e "select count(*) from information_schema.tables where table_schema='property_revenue'; select count(*) from property_revenue.flyway_schema_history;"
```

正常应输出 `70` 和 `40`。

## 启动后端

默认配置已经指向本地 Docker MySQL：

```powershell
cd D:\物业管理\backend
mvn spring-boot:run
```

健康检查：

```powershell
Invoke-RestMethod http://localhost:8580/api/health
```

生产或其他服务器部署时，建议使用环境变量覆盖数据库和安全配置：

```powershell
$env:DB_URL="jdbc:mysql://数据库地址:3306/property_revenue?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false"
$env:DB_USERNAME="property"
$env:DB_PASSWORD="请替换为生产密码"
$env:JWT_SECRET="请替换为足够长的生产密钥"
$env:SENSITIVE_ENCRYPTION_KEY="请替换为敏感字段加密密钥"
$env:CORS_ALLOWED_ORIGINS="https://管理端域名,https://业主端域名"
mvn spring-boot:run
```

## 启动管理端

开发运行：

```powershell
cd D:\物业管理\web-admin
npm install
npm run dev
```

访问：`http://localhost:5683`

生产构建：

```powershell
npm run build
```

构建产物在 `web-admin/dist/`。如果部署到 Nginx，需要把 `/api` 反向代理到后端 `http://后端地址:8580`。

## 启动业主端 H5

开发运行：

```powershell
cd D:\物业管理\owner-miniapp
npm install
npm run dev:h5
```

访问：`http://localhost:5684`

生产构建：

```powershell
npm run build:h5
```

构建产物在 `owner-miniapp/dist/build/h5/`。真机或线上环境建议设置 `VITE_API_BASE` 为后端地址。

## 上线注意事项

- 修改 `deploy/docker-compose.yml` 或生产数据库中的默认密码，避免继续使用演示密码。
- 生产环境必须替换 `JWT_SECRET`、`SENSITIVE_ENCRYPTION_KEY`。
- 按实际域名设置 `CORS_ALLOWED_ORIGINS`，不要直接放开所有来源。
- 微信、支付宝、银行、短信、实名接口上线前，参考 `deploy/.env.example` 补齐对应环境变量。
- 如果使用 Nginx 部署前端，必须配置 `/api` 反向代理，否则页面会请求前端自身端口导致接口失败。
- 数据库恢复会执行 dump 文件中的 `DROP TABLE IF EXISTS`，请勿在已有生产库上直接执行，先备份再恢复。
